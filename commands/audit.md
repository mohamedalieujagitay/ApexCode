name: audit
description:
  Scan project files for AI-detectable patterns in prose, comments, identifiers, commits, and docs
---

Scan the current project for AI fingerprints that detectors and experienced developers would flag.
Follow Audit mode in the apexcode skill, which holds the full pattern reference.

If the ApexCode CLI is on PATH, run `apexcode scan` first. If `scripts/` is present, also run
`python3 scripts/stealth_check.py` and `python3 scripts/naming_check.py` on the changed files. Fold
their output into the report below instead of listing it separately.

Check these file types: README.md, CHANGELOG.md, docs/, \*.md, code comments, package.json
descriptions, PR templates, and the last 20 commits (`git log -n 20`).

For each file, look for:

1. **Em dashes** (—) used as separators
2. **Flagged vocabulary**: delve, tapestry, leverage, utilize, facilitate, streamline, paramount,
   pivotal, meticulous, holistic, robust, comprehensive, multifaceted, harness, foster, bolster,
   seamless, cutting-edge, game-changing, revolutionary, groundbreaking, nuanced, intricate,
   elevate, empower, unleash, ensure, enhanced
3. **AI opening/closing cliches**: "In today's...", "It's worth noting...", "In summary...", "Happy
   coding!"
4. **Narrating code comments**: comments that describe what the next line does instead of why
5. **Over-formatting**: bold-label bullets, uniform list lengths, excessive markdown, emoji
6. **Over-descriptive identifiers**: `userAuthenticationToken` style names, templated
   `handleX`/`processX` everywhere
7. **Low burstiness**: 4+ consecutive sentences of similar length
8. **AI git metadata**: Co-authored-by trailers for AI tools or "Generated by" lines in recent
   commits and files
9. **AI code habits**: swallowed errors, try/catch that only logs and rethrows, null checks on
   values the types guarantee, generic names (`data`, `result`, `temp`), single-call wrappers,
   leftover `console.log`/`print`, unused imports or parameters, placeholder `TODO: implement`,
   unrequested example-usage blocks, `else` after `return`, vague error messages
10. **Hallucinated or unsafe code**: imports of packages not in the dependency manifest, calls to
    methods that don't exist, hardcoded secrets/tokens/URLs/IDs, empty or fake implementations,
    duplicated blocks, design patterns with no need, generic error messages like "Something went
    wrong". Full list: `skills/apexcode/references/ai-code-patterns.md`
11. **Over-polished code**: names far longer than their scope needs (`currentProcessedUserData`),
    LLM identifiers (`processedData`, `finalResult`, `validatedData`), needless intermediate
    variables, one small operation split into many functions, docblocks on trivial functions, every
    module forced into the same shape. Short names in small scopes and genuine TODOs are not
    findings. Full guide: `skills/apexcode/references/human-style-code.md`

For each finding:

1. Show the file and line
2. Quote the problematic text
3. Suggest a human-sounding replacement (for code, show the rewritten snippet)
4. Rate: high (em dashes, flagged words, git trailers, swallowed errors, hallucinated imports,
   hardcoded secrets) / medium (cliches, narrating comments, over-formatting, other code habits) /
   low (identifiers, burstiness, minor style)

After the scan, show a summary count by category.
